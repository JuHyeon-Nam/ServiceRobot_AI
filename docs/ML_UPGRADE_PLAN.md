# 모델·운영 고도화 계획

기준일: 2026-10-07. 기존 진단·3D·정비 시스템을 유지하면서 검증 가능한 학습형 PHM 근거와 운영 신뢰성 확장. 작업량 기준 7단계, 약 3~7일의 추가 개발 범위. 아래 미완료 항목은 예약 실행이나 완료 약속이 아닌 후속 작업 계획.

## 이번 작업 완료

| 구분 | 변경 | 확인 결과 |
|---|---|---|
| 공개 PHM 데이터 | NASA 공식 FD001 다운로드·체크섬·출처 기록 | 100대 학습 / 100대 테스트 확보 |
| RUL 학습 | 엔진 분리, 인과적 특징, 후보 4개, 기준선 비교 | MAE 39.08 → 14.38 cycle, RMSE 18.73 cycle |
| 불확실성 | 독립 엔진 보정·split-conformal 구간 | 목표 90%, 테스트 포함률 94%, 평균 폭 65.97 cycle |
| 결과 화면 | 엔진 100대 선택, 예측·정답·구간 그래프, API | AGV 실시간 PHM과 분리 |
| 로봇 데이터 | 장치 ID·목표 시각 보존, 공식 split 자산 중복 차단 | 작은 ZIP fixture로 생성·분리 검증 |
| 진단 학습 | 로봇 holdout 선택, 가중치 후보 3개, 공통 249-feature | 합성 fixture로 실행 검증; 원본 데이터 재학습 미수행 |
| 진단 평가 | 클래스별 recall/F1·오탐·미탐·ECE·승격 조건 | Macro-F1 단독 또는 Accuracy 단독 승격 방지 |
| 운영 모델 보호 | 실험 경로 분리, 인코딩 계약 확인, 자동 승격 금지 | 기존 모델 유지 |

원본 AI-Hub ZIP/NPZ는 현재 작업 환경에서 확보하지 못한 상태. 기존 로봇 진단 Accuracy 93.29%, Macro-F1 0.5838은 **변경 전 저장 지표**. 새로 측정한 NASA 수치와 혼합하지 않음.

## 후속 단계

| 단계 | 목표 | 구현·실험 | 완료 기준 | 의존 조건 |
|---|---|---|---|---|
| 1 | 재현 가능한 PHM 기준 | FD001·holdout·기준선·구간·UI | 보고서·테스트·재현 명령 공개 | **이번 작업 완료** |
| 2 | 일반화 확인 | 학습 엔진 group CV, FD002~FD004 조건 정규화, 비대칭 고장 지연 비용, 엔진 bootstrap 오차 구간 | fold별 성능·조건별 실패 사례·기준선 비교 | 공개 데이터 추가 확보 |
| 3 | 희소 고장 진단 개선 | AI-Hub 데이터 복원, 고정 인코딩, 로봇 holdout, 가중치 비교, 독립 확률 보정 | 기존 모델과 동일 검증셋의 Macro-F1·오탐·미탐·ECE 비교 | **AI-Hub 원본 필수** |
| 4 | 데이터 수집 신뢰성 | 정상 포함 전체 관측 저장, 센서 관측/수신 시각 분리, 중복·역순·지연 처리, 고장/정비 episode | 누락·재연결·지연 fixture에서 라벨 계약 검증 | 실제 센서 없으면 공개 데이터 리플레이 사용 |
| 5 | 예측·정비 연결 | 데이터 기반 열화 리플레이, 모델 버전/출처 표시, 경고 임계값 hysteresis, 불확실 시 점검 우선 | 정상→열화→고장→정비 전 흐름을 원시 관측과 대조 | 엔진 데모를 AGV 고장 모델로 표현하지 않기 |
| 6 | 실행 환경 검증 | Docker clean build, MQTT 왕복·TTL·오프라인, 연속 실행 지연/메모리 | 환경별 결과·지연 p50/p95·복구 로그 | Docker daemon·MQTT broker 필요 |
| 7 | 시연 마감 | 최신 화면·정량 실험·데이터 한계 중심 2~3분 영상, 재현 패키지·설명 문서 | 타인이 처음부터 실행하고 결과 재현 | 촬영·문서·환경 최종 확인 |

원본 데이터 확보 전에도 2·4·5단계 진행 가능. 3단계 성능 개선은 데이터 없이 숫자를 만들지 않으며, 데이터 확보 후 다시 추정. 실제 제조 설비 적용에는 장비 연결·현장 고장 라벨·안전 검증을 별도 기간으로 편성.

## 로봇 재학습 명령

```bash
python src/build_enhanced_dataset.py --base-dir /path/to/AI-Hub --out-dir data/datasets/robot-v2
python src/train_diagnosis.py --data-dir data/datasets/robot-v2 --output data/experiments/diagnosis-v2
python src/evaluate_enhanced.py --data-dir data/datasets/robot-v2 --model-dir data/experiments/diagnosis-v2 --report data/experiments/diagnosis-v2/evaluation.json
```

기존 `train_enhanced.py` 진입점은 새 파이프라인 호출. `groups` 없는 기존 NPZ는 로봇 단위 평가를 증명할 수 없어 재생성 필요. 공식 train/validation에 같은 장치가 있으면 중단하고 분할 정책을 검토. 입력 인코딩이 운영 모델과 다르면 비교 중단; 데이터셋/모델 버전별 동일 인코딩으로 재구성 필요.

후보 선택은 학습 데이터 안의 로봇 holdout에서만 수행. 공식 validation은 선택된 후보와 기존 모델의 최종 비교에 사용. 기존 인코딩 어휘와의 호환을 유지하며, 데이터 builder의 범주 어휘는 두 공식 split을 참고하는 기존 계약 유지. 향후 신규 모델 버전에서는 train-only 인코딩·미지 범주 처리를 별도로 설계.

승격 검토 조건: Macro-F1 최소 0.01 개선, Accuracy 하락 최대 0.005, 정상 오탐률 최대 5%, 고장 미탐률 악화 없음, 모든 클래스 검증 표본 존재. 조건 충족은 후보 자격일 뿐 배포 승인 아님. 가중치 모델의 확률 보정·센서 계약·현장 검증 후 수동 전환.
