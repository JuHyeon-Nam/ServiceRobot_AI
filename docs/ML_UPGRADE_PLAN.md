# 모델·운영 고도화 계획

최초 기준일: 2026-10-07. 최근 갱신: 2026-11-14. 기존 진단·3D·정비 시스템을 유지하면서 검증 가능한 학습형 PHM 근거와 운영 신뢰성 확장. 아래 미완료 항목은 완료 약속이 아닌 후속 작업 계획. 실제 진단 성능 개선에는 원본 데이터 확보와 재평가 필요.

## 로봇별 진단 오류 분석 (2026-11-14)

`asset_error_analysis` 추가. 같은 전체 점수·혼동행렬이라도 고장 미탐이 한 로봇에 집중되는 경우와 여러 로봇에 퍼지는 경우를 구분하기 위한 기술 통계. 저장 모델 단독 평가 결과와, 후보 선택이 끝난 뒤의 공식 Validation 비교 결과에 `asset_error_analysis` 저장. 운영 API·UI·모델·추론 수식은 변경하지 않음.

| 항목 | 정의·적용 |
|---|---|
| 입력 | 평가에 사용한 동일한 정답·argmax 예측·NPZ `groups` 로봇 ID. 추가 추론·센서 생성 없음 |
| 출력 | `servicerobot.diagnosis.asset_errors.v1`. 클래스 순서, 전체/로봇별 표본 수·정분류 수·Accuracy·건수형 혼동행렬·클래스별 실제 표본 수 |
| 정상 오탐 | 실제 정상인데 고장으로 예측한 윈도 수 / 실제 정상 윈도 수. 로봇별 건수·비율 및 오탐이 있는 로봇 수 기록 |
| 고장 미탐 | 실제 고장인데 정상으로 예측한 윈도 수 / 실제 고장 윈도 수. 고장끼리의 오분류와 구분하며 로봇별 건수·비율 및 미탐이 있는 로봇 수 기록 |
| 클래스별 미탐 | `fault_misses_by_class`: 각 실제 고장 클래스의 표본 수·정상으로 놓친 수·해당 클래스 내 미탐률. 전체 고장 표본 수가 아닌 해당 클래스의 실제 표본 수를 분모로 사용 |
| 표본 없음 | 실제 정상/고장/해당 고장 클래스가 없으면 관련 비율은 `null`. 오류 건수 0을 오탐·미탐률 0의 근거로 해석하지 않음 |
| 정합성 | 로봇별 혼동행렬과 건수를 더하면 전체 결과 복원. 전체 비율은 로봇별 비율의 단순 평균이 아닌 전체 건수로 계산 |
| 선택과 분리 | 12개 후보의 내부 holdout 순위에는 미사용. `candidate_selected` 기록 뒤 선택 후보·기존 모델에만 각각 적용. 기존 정확한 Macro-F1·오탐 제한·승격 검토 정책 및 자동 승격 금지 유지 |
| 저장 위치 | 단독 평가 JSON의 `asset_error_analysis`, 실험 JSON의 `candidate.asset_error_analysis` 및 `champion.asset_error_analysis` |

**표본 단위는 센서 윈도이며 독립 고장 사건 수·고장 지속시간이 아님.** 겹치는 윈도와 로봇별 관측량의 영향을 받으므로 로봇별 Accuracy를 일반화 성능이나 별도 Macro-F1로 해석하지 않음. 분포 이동·특정 로봇 편중·클래스 불균형을 조사하는 근거지만 원인의 확정, 통계적 유의성·신뢰구간·현장 성능의 증명은 아님. 로봇 ID의 물리적 진위도 별도로 확인해야 함. 로봇 수에 비례하는 집계 배열·JSON 용량이 추가되며 대용량 실행 시간·RAM은 미측정.

2026-11-14 검증: 합성 라벨 테스트 31개 추가, 관련 67개·전체 576개 통과. 정상 클래스 인덱스 변경·표본 부재·고장 간 혼동·입력 불변성·집계 복원·같은 전체 오류의 서로 다른 로봇 집중도 확인. 임시 LightGBM 단독 평가 및 12개 후보 검색의 통합 검사를 확장해 공식 선택 이후에만 분석하는지, 원래 지표와 집계가 일치하는지 확인. 선택 모델·저장 모델 동일성 및 운영 파일 보존 검사 유지. 현재 AI-Hub ZIP/NPZ 부재로 실제 로봇의 미탐 분포 분석·재학습·성능 재평가 미수행. Accuracy 0.9329 / Macro-F1 0.5838 및 운영 모델·UI 유지.

## 원본 수집 감사 기록 (2026-11-13)

`read_split`의 무기록 `except Exception: continue` 제거. 정상적으로 읽은 JSON 중 제외된 기록의 건수·이유를 집계하고, ZIP 읽기 실패를 단순 파싱 실패로 숨기지 않도록 변경. 성공한 빌드의 `enhanced_meta.json`에 `ingestion_audit` 추가. 클래스별 원시 기록 분포와 이후 생성 윈도 수를 함께 확인할 수 있는 수집 근거이며 모델 성능 평가가 아님.

| 항목 | 적용 |
|---|---|
| 집계 범위 | 기존 탐색 범위인 각 split 라벨 폴더 바로 아래 `*.zip`. ZIP별·split 전체의 멤버/JSON/비JSON/채택 건수 기록 |
| JSON 선택 | 기존과 같이 대소문자를 구분하는 `.json` 접미사 사용. 비JSON은 별도 건수로 집계하며 파싱하지 않음 |
| 제외 사유 | `invalid_utf8`, `invalid_json`, `record_parse_error`, `missing_error_code`, `not_assigned_error_code` 구분 |
| 레코드 파싱 | 기존 `parse_record`의 `AttributeError`·`TypeError`는 `record_parse_error`로 집계. 전체 필드의 스키마·품질 검증이라는 의미는 아님 |
| 라벨 정책 | `errorCode=None`과 `NOT_ASSIGNED` 제외 정책 유지. 채택된 클래스별 원시 기록 수를 `accepted_by_class`에 기록 |
| 오류 전파 | ZIP 열기·읽기·CRC 오류와 위 처리 범위 밖 예외는 중단. 불완전한 split을 완료된 감사 결과로 반환하지 않음 |
| 중복 멤버 이름 | `ZipInfo`별로 읽도록 변경. 같은 이름이 여러 번 들어간 ZIP에서 마지막 멤버를 반복해서 읽던 문제 수정. 기록을 임의로 중복 제거하지 않으며 관측 시각 중복 검사는 후속 단계에서 유지 |
| 기록 방식 | ZIP별 진행 로그와 split별 제외 사유 출력. 메타의 `servicerobot.dataset.ingestion.v1`에 두 공식 split 집계 저장. `read_split`의 기존 3개 반환값 유지, 선택적 `audit` 인자로 집계 전달 |

집계 관계는 `members = json_members + non_json_members`, `json_members = accepted_records + 제외 사유별 건수 합`, `accepted_records = accepted_by_class 합`. 성공한 빌드에서는 `accepted_records`가 `sequence_audit`의 입력 기록 수와 일치. **원시 기록 수와 학습 윈도 수는 다름.** 합성 통합 검사에서는 split마다 JSON 40개 중 5개 제외 → 원시 기록 35개 채택 → 30시점 이력 계약으로 윈도 5개 생성 확인. 실제 데이터 비율이 아님.

UTF-8·JSON·알려진 레코드 파싱 실패는 집계 후 계속 처리하므로 누락률 제한을 강제하는 기능은 아님. 누락 센서의 기존 숫자 기본값 대체도 유지하며, 채택은 모든 필드가 유효하거나 실제 고장이 정확히 라벨링됐다는 뜻이 아님. 제외된 기록의 고장 클래스나 제외가 Macro-F1에 미친 영향은 이 집계만으로 판단할 수 없음. 원본 전체의 확보 여부·출처 진위·파일 해시·실행 중 입력 불변성을 증명하지 않으며, 실패 시 독립 감사 JSON을 별도 저장하지 않음. 성공 빌드의 메타 저장 전 중단되면 메모리 집계와 이미 출력된 진행 로그만 존재.

2026-11-13 검증: 합성 ZIP·예외 주입 테스트 29개 추가, 관련 130개·전체 545개 통과. 다중 ZIP의 클래스별·사유별 집계 등식, 대소문자 접미사, 같은 이름의 실제 엔트리 구분 확인. 원본 ZIP 불변성·기존 숫자 기본값/반환 계약·NPZ 로더와 재생 정렬 호환 검사. 실제 CRC 훼손 ZIP 및 읽기/예상 밖 파서 오류 중단, 완료되지 않은 감사 결과 미반환 확인. 현재 AI-Hub ZIP/NPZ 부재로 원본 재생성·재학습·성능 재평가 미수행. Accuracy 0.9329 / Macro-F1 0.5838 및 운영 모델·UI 유지.

## 데이터셋 생성 경로 보호 (2026-11-12)

`build_enhanced_dataset.py`가 기존 출력 경로에 NPZ·메타·재생 파일을 덮어쓰던 동작 제거. 잘못된 `--out-dir`로 이전 검증 데이터나 운영 인코딩 메타가 바뀌는 상황을 방지. 센서값·윈도 생성·클래스 매핑·공식 분할 정책은 변경하지 않음.

| 항목 | 적용 |
|---|---|
| 시작 전 검사 | 이미 존재하는 파일·폴더·심볼릭 링크는 ZIP 읽기 전 거부. 빈 폴더·끊어진 링크도 거부하며 새 경로만 허용 |
| 저장 경로 확보 | 데이터 검사를 통과한 뒤 `mkdir(exist_ok=False)` 실행. 파싱 도중 다른 실행이 같은 경로를 생성했으면 파일을 추가하지 않고 중단 |
| 개별 파일 | NPZ 2개·재생 Parquet은 `xb`, 메타 JSON은 `x` 모드로 생성. 경로 확보 후 생긴 동일 이름 파일·링크도 덮어쓰지 않음 |
| 저장 순서 | Training NPZ → Validation NPZ → 재생 Parquet → 메타 JSON. 앞선 파일 저장이 실패하면 이 실행의 메타를 생성하거나 완료 문구를 출력하지 않음 |
| 실패·재실행 | 생성 도중 실패한 파일은 자동 삭제하지 않음. 부분 산출물과 충돌 파일 보존. 같은 경로 재실행은 거부하며 새 경로 지정 필요 |

```bash
python src/build_enhanced_dataset.py --base-dir /path/to/AIHub --out-dir data/datasets/robot-v3
```

`--out-dir`는 명령 실행 전에 만들지 않으며, 기본 `data/datasets/robot-v2`가 이미 있으면 다른 새 경로 사용. 출력 파일명과 `X/S/y/groups/target_times` 계약, 재생 행 정렬은 유지. 기존 데이터·운영 모델은 읽기 전용으로 보존.

**전체 데이터셋의 원자적 저장·자동 복구 기능은 아님.** 디스크 부족·프로세스 중단 등으로 부분 NPZ/Parquet이 남을 수 있고 메타 기록 자체가 실패하면 빈/부분 JSON도 남을 수 있음. 완료 여부·파일 내용·실패 원인을 확인하고 새 경로에서 재실행. 쓰기 중 악의적인 디렉터리 교체나 전원 장애에 대한 내구성 보장은 범위 밖. 임시 데이터 사본을 추가 생성하지 않지만 기존 폴더를 자동 정리하지도 않으며, 디스크 용량·RAM 절감이나 모델 품질 향상을 의미하지 않음.

2026-11-12 검증: 합성 ZIP·파일 충돌·쓰기 실패 테스트 25개 추가, 관련 101개·전체 516개 통과. 기존/빈 폴더·파일·심볼릭 링크 거부, 운영 디렉터리 바이트 보존, 파싱 도중 경로 생성 및 파일별 생성 충돌 시 기존 내용 보존 확인. NPZ·Parquet·메타 실패 후 미완료 상태 보존·완료 문구 미출력·재실행 거부, 정상 생성 시 원본 ZIP 불변성과 메타 마지막 저장·로더/재생 정렬 호환 확인. AI-Hub ZIP/NPZ 부재로 실제 데이터 재생성·재학습·성능 재평가 미수행. Accuracy 0.9329 / Macro-F1 0.5838 및 운영 모델·UI 유지.

## 후보 모델 보관 최적화 (2026-11-11)

`train_candidates`가 실험 목록에 후보 모델 12개를 모두 보관하던 구조 변경. 모든 후보를 기존대로 학습·평가하고, 각 단계의 현재 선택 선두 모델만 보관. 과거 후보의 지표·반복 이력은 모두 유지하며 모델 객체 참조만 정리.

| 항목 | 적용 |
|---|---|
| 선택 기준 | 기존 `select_candidate` 재사용. 정상 오탐 제한을 만족하는 후보 중 정확한 Macro-F1 최대, 정확한 동점은 먼저 등장한 후보 유지 |
| 단계별 보관 | 새 후보를 평가할 때 누적 지표에서 선두 확인. 선두가 바뀌면 모델 참조 교체, 다음 후보 생성 전 완료된 선두 모델 하나만 명시적으로 보관 |
| 제한 미충족 | 제한을 만족하는 후보가 없으면 기존 분석용 fallback 유지. 첫 제한 통과 후보가 나오면 해당 풀로 전환 |
| 정책 방어 | 향후 순위 정책이 바뀌어 이미 보관 대상에서 제외한 후보를 다시 고르면 `selection_failed` 기록 후 중단. 다른 모델을 대신 저장하지 않음 |
| 기록·저장 | 모든 후보의 JSON·CSV·JSONL 지표 보존. 최종 선두만 기존 출력 모델로 저장하며 탈락 모델 파일을 추가 생성하거나 최종 후보를 재학습하지 않음 |
| 실행 설정 | `candidate_model_retention`에 전략·후보 사이 완료 모델 보관 상한·전체 지표 보존 여부 기록. 실험 JSON·시작 JSONL에 포함 |

고정된 현재 순위에서 이전 단계의 탈락 후보는 이후 새 후보 추가만으로 선두가 될 수 없다는 성질을 사용. 검사 대상은 학습 내부 로봇 holdout이며 공식 Validation은 모든 후보 학습 종료 후 선택된 모델과 기존 모델의 비교에만 사용. 자동 운영 모델 승격 금지 유지.

## 원시 배열 보관 범위 축소 (2026-11-10)

학습·사전 점검·단독 평가에서 사용이 끝난 원시 센서 `X`와 맥락 `S`의 참조를 제거하도록 변경. 이전에는 특징 계산 뒤에도 원시 배열과 최종 특징 행렬을 함께 보관. 이번 변경은 메모리 객체의 수명 관리이며 원본 파일 삭제·표본 축소·디스크 저장 형식 변경이 아님.

| 경로 | 동작 |
|---|---|
| 공통 로더 | `load_dataset(..., keep_raw=False)` 추가. 센서·라벨 dtype·로봇 ID 등의 기존 검사를 통과한 뒤 반환 딕셔너리에서 `X/S` 제외 |
| 기존 호출 호환 | `keep_raw=True`가 기본값. 원시 배열을 사용하는 기존 호출은 `X/S`를 그대로 받음 |
| 후보 학습 | 각 split의 배치 특징 계산 후 `X/S`를 보관하지 않음. 학습 원시 배열을 보관한 채 Validation을 로딩하는 구조 제거 |
| 사전 점검 | 각 split의 원시 배열 검사 후 `y/groups`만 유지. 특징 생성·학습·추론 미호출 유지 |
| 단독 평가 | 메타·클래스 검사와 특징 계산 후, Booster 로딩·추론 전에 `X/S` 참조 제거 |
| 기록 | 사전 점검 보고서와 실험/평가의 `feature_construction`에 `raw_sensor_arrays_retained=false` 명시 |

라벨·로봇 ID·특징 행렬은 보존하며 공식 분할 중복 검사·클래스별 표본 집계·후보 선택·평가 기준은 동일. 마지막 검사 배치의 NaN·무한대와 잘못된 ID·라벨은 메모리 보관 옵션과 무관하게 거부. 입력 NPZ를 쓰거나 덮어쓰지 않음.

**전체 NPZ를 읽지 않는 기능은 아님.** 각 split의 원시 배열은 검사·특징 계산 중에 RAM에 필요하며 전체 특징 행렬·LightGBM·DataFrame 등도 메모리를 사용. 파이썬 참조 제거가 운영체제 RSS의 즉시 감소를 보장하지 않음. 실제 대용량 peak RSS·절감 비율·실행 시간과 디스크 용량 감소는 검증하지 않았고, ZIP 원시 기록 누적·샤드 처리·외부 메모리 학습은 후속 범위.

2026-11-10 검증: 합성 테스트 14개 추가 및 기존 12개 후보·사전 점검 통합 검사 확장. 관련 141개·전체 484개 통과. 원시 배열 보관 유무에 따른 반환 특징·라벨·로봇 ID의 동일성, 입력 파일 불변성, 검사 생략 방지 확인. 약한 참조·GC 검사로 비보관 모드의 원시 배열이 회수 가능한지 확인하고 단독 평가의 Booster 로딩 이전 참조 해제를 검사. 실제 AI-Hub ZIP/NPZ 부재로 원본 재학습·성능 재측정 미수행. ## 원본 시퀀스 시간 계약 (2026-11-08)

## 후보 비교 근거 검증 (2026-11-05)

## Macro-F1 기준 반복 선택 (2026-11-04)

기존 후보 학습은 반복 횟수 선택에 기본 로그손실, 후보 간 최종 선택에 Macro-F1을 사용하는 구조. 새 후보 절차는 학습 내부 로봇 holdout의 무가중 Macro-F1을 기본 early stopping 지표로 사용. 트리의 학습 목적함수는 기존 `multiclass` 유지. **Macro-F1을 직접 미분해 학습하는 구현이 아니라, 생성된 반복 중 사용할 모델을 선택하는 기준 변경.**

| 항목 | 적용 |
|---|---|
| 평가 함수 | `macro_f1_eval`, 클래스 수를 고정한 Macro-F1, 표본 가중치 미사용 |
| 반복 선택 | Macro-F1 최대화, 개선 없는 40회 후 중단, 동일 최고 점수는 먼저 도달한 반복 유지 |
| 기본 지표 간섭 방지 | `metric="None"`으로 자동 기본 지표 제외, `first_metric_only=True` |
| 비교 옵션 | `--iteration-metric multi_logloss`로 로그손실 최소화 기준 실행 가능 |
| 저장 | 후보별 `iteration_history`, 실행 설정 `iteration_selection`, CSV의 `iteration_metric`, 후보 메타의 기준 지표 |
| 공식 Validation | 반복 횟수·후보 선택에 미사용. 선택된 후보의 최종 비교에만 사용 |

점수 이력은 첫 번째 값이 1회차이며 중단까지의 검증 점수 보존. `best_iteration`은 1부터 시작. 두 반복 선택 방식을 비교해 사용할 방법을 정할 때에도 학습 내부 holdout 정보만 사용하며, 공식 Validation 결과를 보고 기준을 고르지 않음. 정상 오탐 제한에 따른 후보 필터와 자동 운영 모델 승격 금지는 유지. 오탐 제한은 후보의 선택 반복에 적용하며 회차별 제약 최적화는 아님.

LightGBM 4.6.0의 [기본 지표 제외 설정](https://lightgbm.readthedocs.io/en/v4.6.0/Parameters.html#metric-parameters)과 [early stopping 동작](https://lightgbm.readthedocs.io/en/v4.6.0/pythonapi/lightgbm.early_stopping.html)을 확인하고 실제 라이브러리로 합성 테스트. 완전히 맞히는 점수가 유지될 때 첫 최고 반복으로 선택되는지, 로그손실 옵션은 최소값 반복을 선택하는지, 12개 조합의 회차 이력과 선택 결과가 일치하는지 검사.

2026-11-04 검증: 테스트 16개 추가 및 기존 통합 검사 확장, 전체 211개 통과. 합성 데이터의 콜백·학습 선택 절차 검증이며 실제 AI-Hub 재학습이나 성능 향상 검증이 아님. 기존 운영 모델·UI와 Accuracy 0.9329 / Macro-F1 0.5838 유지. 실제 점수 개선 여부는 원본 확보 후 평가 필요.

## 진단 검색 개선 (2026-11-02)

정상 언더샘플링과 클래스 가중치의 효과를 분리하기 위한 비교 절차 구현. 이전 코드는 무가중치 후보만 정상 최대 3배로 줄이고 가중치 후보는 전체 학습 표본을 사용해 두 조건의 효과가 함께 바뀌는 구조. 현재는 다음 두 축을 같은 로봇 holdout에서 조합해 총 12개 후보 비교.

| 비교 축 | 조건 |
|---|---|
| 정상 표본 | 전체 유지, 고장 표본 총합의 최대 2배·3배·5배 |
| 가중치 | `unweighted`, `sqrt_balanced`, `balanced` |
| 공통 조건 | 동일 fit/selection 로봇, seed, 249개 특징, LightGBM 설정 |
| 후보 선택 | 정상 오탐률 제한을 만족하는 후보 중 선택 Macro-F1 최대 |
| 공식 Validation | 후보 선택 후 선택된 후보와 기존 모델의 최종 비교에만 사용 |

샘플링은 fit 부분의 정상 표본에만 적용. 모든 고장 표본 유지, 선택·공식 검증 데이터는 원래 분포 유지. 비율은 상한이므로 정상 표본이 이미 적으면 추가 생성하지 않음. 기본 seed는 42이며, seed를 고정한다고 다른 데이터나 환경에서 동일 성능을 보장하는 것은 아님.

학습과 선택 양쪽에 모든 클래스가 존재하도록 로봇 단위 분할 검사 강화. 한 클래스가 로봇 한 대에만 있으면 중단. 각 클래스가 두 대 이상에 있더라도 64회 분할 시도에서 완전한 클래스 구성을 찾지 못하면 중단하므로 자산 분포 검토 필요. 같은 로봇의 윈도를 양쪽에 나누어 우회하지 않음.

| 산출물 | 기록 내용 |
|---|---|
| `experiment_report.json` | 12개 후보의 클래스별 precision/recall/F1/support·혼동행렬·오탐·미탐, 선택 후보와 기존 모델의 공식 평가, 분할별 클래스 표본 수·독립 로봇 수 |
| `training_events.jsonl` | 실행 시작, 후보 시작·완료·실패, 전체 완료. 완료된 후보 결과는 후속 실패 시에도 보존 |
| `selection_results.csv` | 후보별 샘플링·가중치·학습 표본 수·Accuracy·Macro-F1·오탐·미탐 비교표 |
| 모델·메타데이터 | 선택된 후보만 별도 출력. 운영 모델 변경 없음 |

보고서에 입력 NPZ·인코딩 메타·기존 모델·학습 코드의 SHA256 및 Python/NumPy/pandas/LightGBM/scikit-learn 버전 기록. 출력 폴더가 비어 있지 않으면 중단하여 이전 결과 보존. `data_kind`는 호출자가 선언한 출처이며 독립적인 진위 검증이 아님. `synthetic_fixture`·`unspecified` 실행은 승격 검토 대상에서 제외. 선택 오탐 제한을 만족하는 후보가 없어도 검토 대상에서 제외하며 자동 승격은 모든 경우 비활성.

**실행 검증 범위:** 불균형 합성 fixture에서 12개 조합 학습·저장, 실제 샘플링 표본 수, 검증 호출 순서, 실패 기록 보존, 재실행 덮어쓰기 차단, 운영 모델 바이트 불변성 테스트. 실제 AI-Hub ZIP/NPZ는 현재 환경에 없어 원본 재학습 미수행. **공식 Accuracy 0.9329 / Macro-F1 0.5838은 변경 없음.** 이번 절차 구현을 과거 SMOTE 또는 2·3·5배 실험의 실행 증거로 소급하지 않음.

2026-11-02 검증: `python -m pytest -q tests/test_diagnosis_search.py tests/test_ml_upgrade.py` 52개 통과, `python -m pytest -q tests` 전체 158개 통과. 테스트 통과 수는 파이프라인 검증 결과이며 모델 성능 지표가 아님.

후속 우선순위:

1. AI-Hub 원본 복원, 장치 ID·인코딩 호환성과 클래스별 독립 로봇 수 확인.
2. 원본으로 동일 조건 검색 실행. 부족한 고장 자산은 별도 수집하거나 평가 한계로 기록.
3. 학습 데이터 내 여러 로봇 분할·seed로 선택 안정성 확인. 공식 Validation에 맞춘 반복 튜닝 금지.
4. 독립 보정 데이터의 확률 보정, 클래스별 미탐 분석과 최종 공식 평가. Macro-F1뿐 아니라 오탐·미탐·희소 클래스 성능 동시 확인.

## 로봇 재학습 명령

```bash
python src/build_enhanced_dataset.py --base-dir /path/to/AI-Hub --out-dir data/datasets/robot-v2
python src/train_diagnosis.py --data-dir data/datasets/robot-v2 --preflight-only --preflight-report data/experiments/diagnosis-readiness-run-001.json
python src/train_diagnosis.py --data-dir data/datasets/robot-v2 --output data/experiments/diagnosis-run-001 --data-kind aihub_recorded --normal-ratios 0 2 3 5
python src/evaluate_enhanced.py --data-dir data/datasets/robot-v2 --model-dir data/experiments/diagnosis-run-001 --report data/experiments/diagnosis-run-001/evaluation.json
```

원본 AI-Hub 데이터임을 확인한 경우에만 `--data-kind aihub_recorded` 사용. `--normal-ratios 0`은 전체 정상 유지이며, `--weight-modes unweighted`로 샘플링 효과만 비교 가능. 실행마다 새 출력 폴더 사용. 합성 테스트 결과를 실제 성능 근거로 사용하지 않음.

기존 `train_enhanced.py` 진입점은 새 파이프라인 호출. `groups` 없는 기존 NPZ는 로봇 단위 평가를 증명할 수 없어 재생성 필요. 공식 train/validation에 같은 장치가 있으면 중단하고 분할 정책을 검토. 입력 인코딩이 운영 모델과 다르면 비교 중단; 데이터셋/모델 버전별 동일 인코딩으로 재구성 필요.

후보 선택은 학습 데이터 안의 로봇 holdout에서만 수행. 공식 validation은 선택된 후보와 기존 모델의 최종 비교에 사용. 기존 인코딩 어휘와의 호환을 유지하며, 데이터 builder의 범주 어휘는 두 공식 split을 참고하는 기존 계약 유지. 향후 신규 모델 버전에서는 train-only 인코딩·미지 범주 처리를 별도로 설계.

승격 검토 조건: Macro-F1 최소 0.01 개선, Accuracy 하락 최대 0.005, 정상 오탐률 최대 5%, 고장 미탐률 악화 없음, 모든 클래스 검증 표본 존재. 조건 충족은 후보 자격일 뿐 배포 승인 아님. 가중치 모델의 확률 보정·센서 계약·현장 검증 후 수동 전환.
